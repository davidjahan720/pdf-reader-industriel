    3. DXF -> entites dimensionnees (ezdxf)

COUCHE 2 — LECTURE DE FICHIERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PyMuPDF (fitz)       pip install pymupdf
  - rasterisation PDF -> pixmap (zoom 5x = ~600 DPI equivalent)
  - extraction texte vectoriel via page.get_text("words")

ezdxf                pip install ezdxf
  - parsing DXF, iteration modelspace
  - entites supportees : DIMENSION (actual_measurement), TEXT, MTEXT
  - limite : DXF 3D (3DSOLID/POINT/LINE/ARC) ne contient pas de cotes

Pillow               pip install Pillow
  - ouverture images : PNG, JPG, JPEG, TIF, TIFF, BMP, WEBP

Formats supportes :
  .pdf  -> texte vectoriel OU rasterise vers OCR
  .dxf  -> entites DIMENSION/TEXT extraites
  .png/.jpg/.tif/.bmp/.webp -> OCR direct

Limites connues :
  - PDF image (capture d'ecran de site web) : aucun texte vectoriel
    -> bascule automatique sur OCR avec message d'avertissement
  - DXF export modele 3D : aucune entite cotee
  - Symboles GD&T graphiques (parallelisme, perpendicularite, planeite)
    invisibles a l'OCR -> a completer manuellement

  | Plateforme         | Temps bride.pdf   |
  +--------------------+-------------------+
  | CPU local (i7)     | ~130 s            |
  | GPU NVIDIA A2 16GB | ~25-35 s (estime) |
  +--------------------+-------------------+


PIPELINE EN 4 PASSES :

Passe 1 — OCR brut (zoom 5x)
  reader.readtext(raw_image, rotation_info=[90,180,270],
                  text_threshold=0.4, low_text=0.25)

Passe 2 — OCR sur image pretraitee
  pipeline : upscale 3000px -> grayscale -> deskew Hough -> denoise
             -> CLAHE (clipLimit=2.0, 8x8) -> threshold adaptatif Gauss
             -> dilation 2x2

Passe 3 — OCR sur image sharpened
  unsharp mask : addWeighted(gray, 1.8, gaussianBlur(gray,3), -0.8, 0)

Passe 4 — OCR par tuiles 2x2 (recouvrement 20%)
  Decoupe l'image en 4 quadrants, OCR chaque tuile separement
  Re-mappe les coordonnees en espace image global
  Objectif : capter petites annotations (ex : R4.1 que les passes
             globales manquent)


CONSOLIDATION (vote multi-passes) :

Clustering positionnel single-link (threshold = 50 pixels)
Pour chaque cluster, score par label :
  1. nombre de detections (count multi-passes)
  2. confiance moyenne
  3. longueur du label
  4. penalite pour entiers courts isoles

Garde-fous :
  - dim <= 9 sans decimale et det=1  -> rejete (bruit)
  - dim <= 9 dans zone cartouche (y > 0.82*H) avec det<3 -> rejete
  - Suppression des fragments OCR a meme position

COUCHE 4 — CORRECTIONS POST-OCR (_correct)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Patterns connus :
  "1350"       -> "135°"   (degre lu comme zero)
  "8.2 Hz8"    -> "8.2 H8" (fit ISO mal decoupe)
  "Ra 3,2"     -> "Ra3.2"  (rugosite)
  "RZ7"        -> "Rz7"    (Z majuscule au lieu de minuscule)
  "R 4.1"      -> "R4.1"   (rayon avec espace)
  "R41"        -> "R4.1"   (heuristique : rayon a deux chiffres = decimal)
  "X_Y"        -> "X.Y"    (underscore au lieu de point)
  ","          -> "."      (decimale europeenne)

COUCHE 5 — PARSER & CLASSIFICATION (core/parser.py)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

re (regex Python natif)

Types reconnus :
  dim         dimension simple        ex : 8, 10, 20, 11.5
  iso_fit     ajustement ISO          ex : 40 H7, 8.2 H8, 25 h6
  rayon       rayon                   ex : R4.1, R12
  angle       angle                   ex : 135°, 45°
  rugosite    etat de surface         ex : Ra3.2, Rz7
  gdt         tolerance GD&T          ex : ⊕ 0.1 A B, ⏥ 0.1 A
  gdt_value   valeur GD&T orpheline   ex : "0.1 A B" (sans symbole graphique)

Heuristique GD&T (core/ocr.py / _merge_gdt_with_items) :
  gdt_value detecte avec >= 2 datums  -> symbole ⊕ (position quasi-certain)
  gdt_value detecte avec  = 1 datum   -> symbole ⏥ (planeite plus frequente)
  Valeur 0.1 sans datum               -> non detecte (limite OCR)

Table ISO 286 integree :
  Zones   : H6, H7, H8, H9, h6, h7, g6, f7
  Plages  : 0-3, 3-6, 6-10, 10-18, 18-30, 30-50, 50-80, 80-120, 120-180, 180-250 mm
  Calcul  : ES (ecart superieur) et EI (ecart inferieur) en mm avec signe
            ex : 40 H7 -> ES=+0.025, EI=+0

Symboles GD&T Unicode (ISO 1101) :
  ⏥  planeite          ⊕  position        ∥  parallelisme
  ⊥  perpendicularite  ∠  angularite      ○  circularite
  ⌭  cylindricite      ◎  concentricite   ≡  symetrie
  ↗  battement         ↗↗ battement total
  ⌒  profil de ligne   ⌓  profil de surface

COUCHE 6 — EXPORT EXCEL (core/excel.py)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

xlrd                 pip install xlrd
xlwt                 pip install xlwt
xlutils              pip install xlutils

Strategie : copie de la template .xls (preservant styles + cellules
            fusionnees) via xlutils.copy.copy, puis ecriture des cellules
            par ws.write.

Structure du PV de controle (Feuil1) :
  L12-13   en-tetes
  Col B    cote nominale       ecriture a partir de B15 (row=14, base 0)
  Col C    tolerances ES / EI  (iso_fit uniquement, 2 lignes)
  Col I    OBSERVATION         (vide en v2)
  Pas      une ligne sur deux (cellules fusionnees)

Conventions de format :
  iso_fit  -> col B "40 H7", col C ligne N ES, ligne N+1 EI
  rugosite -> col B "Ra 3,2" (espace + virgule decimale)
  gdt      -> col B label complet avec symbole Unicode
  dim/rayon/angle -> col B label tel quel

Pre-requis : Python 3.11+ recommande

  pip install -r requirements.txt

Ou explicitement :
  pip install pymupdf ezdxf Pillow opencv-python numpy
  pip install xlrd xlwt xlutils
  pip install easyocr

Note : easyocr installe PyTorch (~800 MB) automatiquement.
Les modeles EasyOCR (~150 MB) se telechargent au premier lancement
dans %USERPROFILE%/.EasyOCR/ (Windows) ou ~/.EasyOCR/ (Linux).

Pour le GPU (serveur A2) :
  Installer CUDA Toolkit 11.8 ou 12.x compatible PyTorch
  Reinstaller torch avec : pip install torch --index-url
                            https://download.pytorch.org/whl/cu121
